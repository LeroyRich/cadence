# Cadence Music Tagger

Cadence is a DSM 7 music metadata editor designed to work directly on files stored on the NAS. It provides a browser-based library, single and multi-file tag editing, metadata suggestions, artwork, folder organization, a mandatory review step, and background jobs.

## Supported audio

| Format | Extensions | Tag editing | Embedded art replacement |
| --- | --- | --- | --- |
| MP3 | `.mp3` | ID3 | Yes |
| FLAC | `.flac` | Vorbis comments | Yes |
| M4A / M4B | `.m4a`, `.m4b` | MP4 atoms | Yes |
| Ogg Vorbis | `.ogg`, `.oga` | Vorbis comments | Yes |
| Opus | `.opus` | Vorbis comments | Yes |
| WAV | `.wav` | ID3 | Yes, but player support varies |
| AIFF | `.aif`, `.aiff` | ID3 | Yes, but player support varies |
| WMA / ASF | `.wma`, `.asf` | ASF | No |

Cadence preserves tag fields it does not edit. M4A/M4B track and disc totals remain visible. It intentionally excludes `.mp4` so a video library cannot be indexed accidentally.

## Features

- Add approved folders at any time; no music path is assumed. Adding a folder automatically starts a background scan. Use **Scan folders** to refresh the index after changes made outside Cadence, or enable the daily refresh in Settings.
- Sort the full indexed library by title/filename, library-root-relative path, artist, album, track number, disc number, format, or length in either direction, across pages of 100 (default), 250, 500, or 1,000 tracks. Previewable embedded cover art appears beside each track; an unavailable-artwork symbol distinguishes an embedded image that cannot be previewed from a track with no artwork.
- Keep the selection bar and sortable table headers visible while scrolling tracks. The selection count, page size, range, page arrows, page jump, and **Columns** control sit above the headers; the same pagination controls remain below the list. The page jump shows `Page X` for the current page and bare numbers for other pages. Use **Columns** to show, hide, or reorder columns. Drag a header edge to resize it, or focus the handle and use the arrow keys; Track, Disc, Format, and Length have fixed widths. Column choices and widths are saved in this browser. Row selection and hover colors extend across the full list width, including space after the last visible column.
- The Library filter beside **Select entire list** finds missing embedded artwork, invalid characters in tags, lowercase or uppercase titles, files directly inside artist folders, and missing title, artist, album, track number, or year tags. Each missing field has its own filter. **Invalid characters in tags** finds hidden control characters, surrogate characters, or the � replacement symbol in any displayed tag field, including each genre value; ordinary punctuation and accented letters remain valid. Existing indexed tags are checked automatically on upgrade, without reading audio files again. Case filters require at least one cased letter; numbers and punctuation are ignored. Missing year includes Date values without a recognizable year.
- **Tag search** replaces Genre search in the list filter. Its field dropdown defaults to **All tags**, with choices for Title, Artist, Album, Album artist, Track number, Disc number, Date / Year, Genre, and Comment. An empty search shows all items in the selected library; enter text in the search box to find case-insensitive, literal substring matches in saved tag values. Genre searches check every genre value. Paths and metadata field names are excluded from Tag search. Queued changes affect search only after commitment; use **Scan folders** after external edits.
- Choose **Tracks, Albums, Artists, Genres, Decades, or Years** between the search box and library dropdown. Each fresh session starts in Tracks. Other views show one row per group with their own sortable columns, track counts, and total length. Albums group by album name plus album artist, falling back to track artist; matching identities merge across folders. Artists use the track Artist field without splitting combined names. Genres include each saved genre separately. Years and decades use the recognizable year in Date; decades display as `1990s`. Group identities ignore case and surrounding whitespace. Missing values appear as Unknown album, Unknown artist, No genre, Unknown year, or Unknown decade; unknown albums remain separated by artist.
- Ordinary grouped search matches group names, plus album artist in Albums. **Tag search** searches member tracks and reveals their groups. Other list filters reveal groups containing a matching track; summaries and edits always cover the whole group within the selected library. Clicking a group opens the existing editor for all its tracks, with shared/mixed values and artwork. Selecting overlapping groups deduplicates tracks. Selection counts show both groups and affected tracks; the 5,000-track limit applies to the expanded selection, including whole-list selection. All existing edit, organization, deletion, queue, review, and commit actions apply to those tracks. In particular, deleting a group deletes all its scoped member tracks after the normal review and commit steps.
- View changes retain search, library scope, and applicable filters while clearing selection, closing the editor, and returning to page one. The unfiltered option follows the view: All tracks, All albums, etc. Empty folders remains available only in Tracks and resets to All when switching views. Column choices, widths, order, and sort are saved separately per view in this browser; existing Tracks column preferences are retained. Group memberships are backfilled from cached metadata on upgrade without rereading audio, then refreshed after scans and commits. Queued edits do not change group membership until committed.
- **Files in the root of artist folder** means files directly inside the first folder under a library root; files directly in the library root or in an album subfolder are excluded. Filters combine with search and the **All libraries** choice across all pages. Changing any filter or search clears track selection, while queued edits remain staged. Filters use indexed, saved metadata and refresh when the list reloads after a commit or scan; use **Scan folders** after external changes. Existing WMA/ASF artwork detection is refreshed on the first scan after this upgrade.
- Edit a single track or select tracks across pages. The header checkbox selects the visible page; **Select entire list** selects all tracks matching the current search and library filter, up to the 5,000-track batch limit. The button is disabled for larger lists, with a hover tooltip explaining how to narrow the list. When that list is fully selected, the button becomes **Deselect entire list** and clears its selection across pages. Once any track is selected, clicking another row toggles its selection instead of opening the editor. Select a track, then **Shift+Click** another row or checkbox to add every track between them on the current page, in the displayed order. Existing selections are retained; repeated Shift+Clicks use the same starting track until another track is selected normally. Changing pages or deselecting the starting track clears that range anchor. Shift+Click without an anchor selects just the clicked track. The 5,000-track selection limit still applies. An open Edit pane follows a multi-selection as it changes, reopening as a fresh edit and discarding unsaved pane edits; queued edits remain available. Batch fields show values shared by every selected file, including queued edits, without applying them again unless changed. An untouched blank mixed field retains each file's value. Clearing a populated batch field stages removal from every selected file and selects its **Clear** checkbox when the field loses focus; the checkbox also clears a mixed field directly.
- The Edit pane groups fields as Artist, Album (including artwork), Track (including the Title field and single-track playback), Genres, Comment, metadata lookup, and File & Folder Organization. Single-track file paths appear at the bottom; batch selections show a warning at the top. The pane opens at the top. Groups stay open; Advanced Track Options and Genre cleanup & compatibility still expand on demand.
- **Advanced Track Options**, directly under Title, can normalize capitalization or remove an exact, case-sensitive text string from each selected title. For example, removing ` (Live)` preserves the leading space in the match and removes every occurrence. Removal runs before normalization. Both options use staged title edits when present and show each result in the before-and-after review; apostrophes remain within words.
- **Add to queue** stages per-file changes on the NAS without writing audio files. Reopening a queued track shows its staged values. **Save changes** reviews the current edit for commit; **Process queue** reviews all queued files for one background commit job. New edits can be queued and a second commit scheduled while another job runs; jobs execute one at a time in submission order, including after a service restart. Files already reserved by a queued or running job cannot be staged again until that job finishes. Review allows individual queue removal, continuing to edit, or cancelling the whole queue; clearing always requires a second confirmation; committing does too unless disabled in Settings. Submitted entries leave the visible queue immediately; failed or skipped entries return when the job finishes so they can be corrected or removed.
- Single-track editing includes authenticated, range-enabled audio playback from the NAS. Browser codec support varies by format. Drag the Edit pane’s left edge to resize it on desktop, or focus that edge and use the arrow keys; its width is saved in this browser. Settings uses two columns on desktop and one on smaller screens. The interface automatically follows the device's light or dark appearance setting. Press **Esc** to dismiss the active modal, expanded editor section, or editor panel.
- Settings → **Commit safety** controls the extra final confirmation when committing, enabled by default. Uncheck **Ask for final confirmation before committing** and save settings to skip only the final OK/Cancel prompt for both Save changes and Process queue. The proposed-changes review always remains; **Cancel all changes** still requires confirmation. The preference is saved on the NAS and applies across browsers.
- Settings → **Library refresh** can run **Scan folders** automatically every day at 3:00 a.m. in the NAS's local time zone. It is off by default. Scheduled scans use the normal background job queue and appear as **Scheduled scan** in Activity; if a scan is already queued or running, that scan covers the day's refresh. A missed 3:00 a.m. while Cadence is stopped is not run later that day. The next refresh occurs at the next local 3:00 a.m.; daylight-saving changes can make the elapsed interval 23 or 25 hours.
- Organize relative to each approved library root: `Artist/file`, `Artist/Album (Year)/file`, or `Existing artist/Album (Year)/file`. The year comes from the track's Date tag, including a staged edit; if no valid year is available, the album folder uses its name alone. A year already at the end of the album name is not appended again. For the last option, the first folder under the library root is treated as the existing artist; files directly in the root go to `Album (Year)/file`. Optionally rename files to `Title`, `Track number - Title`, `Artist - Title`, or `Artist - Album - 00 - Title`, preserving the audio extension.
- **Import tags from filename**, below the folder and rename options, reverses the same four filename patterns for one or multiple tracks, ignoring the audio extension. Imported fields replace existing or staged values; unrelated tags are retained. Leading zeros are removed from track numbers. Import runs before title cleanup, folder organization, and renaming, using the current filename rather than a proposed rename. Patterns use the exact ` - ` separator; artist and album components cannot contain that separator, while titles can. Ambiguous numeric separators and nonmatching filenames are rejected. **Add to queue** validates the whole selection before staging anything; **Save changes** lists nonmatching files as excluded errors in the review. Queued imports are saved as ordinary per-file tag edits, so reopening the editor shows imported values without reapplying the import. Sanitized or truncated filename text cannot recover the original characters or full tags.
- Preview before and after values and destination paths in pages of 50 before committing. Files with collisions or unsupported changes are excluded.
- Look up MusicBrainz matches using text, optionally identify audio with AcoustID and `fpcalc`, and stage Cover Art Archive, uploaded, or URL-fetched artwork for review. A pasted URL fetches a public HTTP(S) JPEG or PNG (up to 10 MB) through the NAS; private-network addresses and nonstandard ports are blocked. The fetched image uses the same preview, queue, and commit flow as an uploaded file.
- Artwork previews read embedded pictures from ID3, FLAC, MP4, Ogg/Opus (including legacy `COVERART`), and WMA/ASF `WM/Picture` tags. When several pictures exist, a usable front cover is preferred. JPEG, PNG, GIF, WebP, and BMP images up to 10 MB can be previewed; replacement artwork remains JPEG or PNG. The Edit pane checks the file directly, reports embedded images it cannot preview, and updates a stale Library artwork indicator. Its artwork preview is 114 × 114 pixels. Multi-selection displays a cover only when every selected track has identical preview image bytes, including queued replacements; differing covers or a mix of present and missing covers show **Mixed artwork**. All-missing selections show **No embedded artwork in selected tracks**. Large selections are checked in batches, and merely viewing shared artwork never stages a replacement. After upgrading, run **Scan folders** once to refresh existing indexed artwork flags; unchanged files with old artwork indexing are rechecked. Folder images such as `cover.jpg` are separate files and are not treated as embedded track artwork.
- Scan and commit in background, with progress, cancellation, and errors. Scans batch index writes to reduce disk activity on slower NAS devices. Activity Details shows job creation, execution start and stop times, and each successfully committed file's completion time. Timestamps unavailable for older jobs display as such. **Clear Completed Jobs** removes only successful jobs; failed, partial, cancelled, and interrupted jobs remain until cleared individually. Clearing or cancelling a waiting job returns previously staged queue edits, but discards unstaged edits submitted through **Save changes**; the UI asks for confirmation first. Running jobs must finish or be cancelled before they can be cleared. Tag edits write directly to the original file; folder and filename changes use a direct rename. Cadence does not make full-file copies, keep audio-file backups, or offer Undo. An interrupted tag write can leave a file partially edited or damaged.

## File deletion and empty folders

At the bottom of **File & Folder Organization**, choose **Delete file(s)** to stage permanent removal. The default is **Do not delete file(s)**. Selecting deletion disables the other edit controls; switching back before staging preserves the current draft. **Add to queue** stages deletion and replaces other queued edits for those files. **Save changes** opens the review. Nothing is deleted until **Commit to disk**; the existing final-confirmation preference still applies. Reopen a queued deletion and choose **Do not delete file(s)** to cancel it through Add to queue, or review and commit its cancellation through Save changes. Mixed selections preserve their individual queued actions until a deletion option is explicitly chosen.

After upgrading from an earlier build, run **Scan folders** once before deleting previously indexed files. This records the file identities needed to reject replaced targets. Existing edits, jobs, and queue entries remain compatible.

**Empty folders**, the last Library filter, discovers folders in the selected library in a background job. Results show a folder icon, folder name, and library-relative path; other data columns stay blank. Search, Title / File and Path sorting, pagination, selection, and Shift+Click work as in the track list. Title / File and Path are temporarily visible; the previous track sort and column choices return when leaving the filter. The folder editor shows paths and a **Delete folder(s)** option, with the same queue and review flow. Files and folders share the 5,000-item selection and queue limits.

Only directories containing zero entries qualify. Hidden files, artwork, symlinks, and even empty child directories make their parent nonempty. Cadence does not traverse symlinks, treat unreadable folders as empty, or allow deletion of an approved library root. Opening the filter, changing library scope, and Scan folders refresh discovery; deletion jobs also refresh results. Loading and partial-scan errors appear above the list.

Deletion review and Activity details identify the operation and exact path. Cadence rechecks each target's identity before removal and uses nonrecursive removal for empty folders. A changed file, replaced target, unavailable path, or folder that gains contents fails without deleting that target; staged failures return to the queue. Successful deletion updates the index. Newly empty parents appear as separate results and are never deleted automatically. Deletions are permanent; Cadence does not create a holding folder, backup, or Undo record.

## Genre editing

The **Genres** editor uses chips for every supported audio format. Type a genre and press Enter or **Add**, choose an indexed genre from the input's suggestions, click a chip to edit it, or use its × button to remove it. Commas and semicolons are literal text when entering a chip. No predefined genre vocabulary is enforced; suggestions come from the library, not an external service.

Two ordinary chips such as `Rock` and `Folk` are valid. If a genre is rejected, Cadence identifies the invalid chip number or limit instead of showing a generic message. Queued genre values are loaded into the chips when the editor reopens; the chips are the only source of new genre edits.

The **Genre action** dropdown works for one or many selected tracks. **Overwrite tracks with selected genre(s)** is the default: the displayed chips become the replacement list when edited. Existing genres appear for a single track or a batch with identical genre lists, including their order. For a mixed selection, no shared chips appear; untouched genres stay unchanged. Remove every chip in Overwrite mode to clear genres. **Add selected genre(s) to each track** and **Remove selected genre(s) from each track** start with empty chip lists, so choose the genres to add or remove. Already-present genres on Add and absent genres on Remove are silently skipped. Each action keeps its own draft chips if you switch between actions. Finish a partially entered chip with Add/Update before queueing or saving.

Under **Genre cleanup & compatibility**, optional per-track cleanup trims whitespace and removes case-insensitive duplicates while retaining the first spelling and order. Optional splitting converts comma/semicolon lists to separate values and also cleans them. Slashes, ampersands, and ordinary punctuation are not separators. Existing comma-separated text is never split automatically. Queue, reopen, review, and job Details retain the individual genre values.

Storage uses ID3 TCON text values for MP3/WAV/AIFF, repeated GENRE comments for FLAC/Ogg/Opus, multiple ©gen text values for M4A/M4B, and multiple WM/Genre attributes for WMA/ASF. Existing numeric ID3 genre references are read as genre names. New ID3 input must use genre names rather than reserved numeric codes or RX/CR. Writing multiple genres to an older ID3 tag automatically permits an ID3v2.4 upgrade by default; the editor's permission checkbox is checked and disabled. Turn off **Automatically allow ID3v2.4 upgrades** in Settings to restore the per-edit checkbox. The proposed-changes review identifies each upgrade. Unrelated edits preserve the original genre frames without additional audio-file reads or copies. A tag upgrade does not re-encode audio. Player interpretation of multiple values still varies; test representative files in Plex or other players. This release does not modify Robot Radio.

The Library now includes **Missing genre** (no nonblank genre values) and **Genre needs review** (possible comma/semicolon lists, duplicates, whitespace, control characters, or Unknown/Unspecified/N/A/None placeholders). Review is a heuristic, not a declaration that the genre is invalid. After upgrading, use **Scan folders** once to populate all genre values, filters, and suggestions. A banner remains while older index entries exist. Opening an editor refreshes its selected legacy entries on demand; no audio tags are written by indexing. Future scans retain the existing unchanged-file optimization.

Internally and in the API, `tags.genre` and new queued genre edits are arrays. Legacy scalar genre edits and already queued jobs remain readable; an old scalar is treated as one genre, not implicitly split. Edited lists support up to 100 genres of 1,000 characters each. The authenticated `/api/genres?q=...` endpoint offers at most 50 indexed suggestions.

## Build an SPK

The package is designed for DSM 7.0 or later and depends on Web Station. It needs Python 3.8 or newer and selects the newest compatible installed interpreter it finds. Python 3.9 remains a compatibility fallback for older NAS models, but is past upstream end of life; update the interpreter when a supported build is available for your DSM. It does not require the older `py3k` package. The generated SPK includes Mutagen 1.47.0 and its license notice.

On a Linux build computer with Python 3 and pip:

```sh
sh build_spk.sh
```

The script creates `Cadence-0.1.0-0054.spk`. Builds are published as release assets rather than committed to this repository, so the current one is attached to the [0.1.0 build 0054 release](https://github.com/LeroyRich/cadence/releases/tag/v0.1.0-0054) (`Cadence-0.1.0-0054.spk`, 245,760 bytes, SHA-256 `215752d07680ecba7074117187cb95ed5453e077b12e493434111942a0efdfbc`). Build 0054 matches the view dropdown height to the other toolbar fields. It includes metadata Tag search and Albums, Artists, Genres, Decades, and Years views with whole-group editing from build 0053. For an offline rebuild, set `MUTAGEN_SOURCE` to a directory containing `mutagen/` and `mutagen-1.47.0.dist-info/`.

## Install on DSM

1. Install **Web Station** from Package Center. Ensure a compatible Python interpreter is available; Synology's **Python 3.9** package is supported.
2. Open Package Center → **Manual Install** and select `Cadence-0.1.0-0054.spk`. When upgrading, install over the existing package so the index and queued changes remain available. The upgrade deletes Cadence's previous `var/backups` folder; first start also removes any remaining backups and Undo history.
3. Choose an administrator password of at least 12 characters in the install wizard.
4. Open Cadence from Package Center or the DSM application launcher. Its HTTPS portal uses port **8788** and forwards internally to the app's loopback-only service on port 8787. Your browser must trust the certificate configured for the NAS's DSM portal.
5. Before browsing folders, in DSM Control Panel → Shared Folder → Edit → Permissions → **System internal user**, grant the `Cadence` package user Read/Write access to each share you intend to edit. Cadence will not change DSM permissions itself. If a subfolder has its own restrictive ACL, grant access there too.
6. In Cadence, choose **Add folder** and browse within a `/volumeN` folder. Cadence starts scanning automatically and shows progress in Activity. Use **Scan folders** later if files or folders change outside Cadence.
7. Optionally enter a MusicBrainz contact email and AcoustID application key in Settings. Audio fingerprint identification also requires a compatible `fpcalc` executable available to the package account; text matching and cover art do not.

## Security on your network

Cadence's package account should have Read/Write access only to the music shares you approve. In DSM's firewall, allow TCP port 8788 from the computers or trusted subnet that use Cadence and deny it from IoT or guest networks. Check IPv6 rules too. Avoid router port forwarding to Cadence; use a VPN if you need access away from home. Apply these firewall rules carefully so you retain DSM access.

The DSM portal uses HTTPS on port 8788 and a loopback-only backend. Ordinary logins use browser-session cookies and expire after 12 hours. **Remember me** is off by default; when selected during login, it keeps that browser signed in for 30 days, including across browser and service restarts. It uses a persistent cookie and a server-side session record containing a hash of the session token. Logout revokes the current session, and changing or resetting the administrator password revokes every session. Use Remember me only on a trusted device. Login attempts are briefly throttled across the service. The app's `server.log` rotates at 5 MB with three retained files; startup failures are written to `startup.log`. Library state and credentials in `library.sqlite3` are private to the package account where that account owns the files. The NAS certificate must be trusted by your browser for HTTPS to protect login traffic.

Cadence no longer makes a transient full-file copy during commit. This reduces temporary disk use, but in-place writes are not atomic: a crash or storage error can leave a file partially edited or damaged. Changes are irreversible in the app. Keep your normal NAS backups or snapshots and test with a small folder first.

## Local development

```sh
python3 -m pip install -r requirements.txt
python3 -m tagger.server --state-dir ./state --set-password
python3 -m tagger.server --state-dir ./state --host 127.0.0.1 --port 8787 --insecure-local-http
```

Open `http://127.0.0.1:8787` locally. Local tests use generated audio fixtures:

```sh
python3 -m unittest discover -s tests -v
node tests/test_library_ui.cjs
```

`ffmpeg` is required only to generate those test fixtures. The app itself needs no FFmpeg for ordinary tag editing.

Grouped browsing uses authenticated `GET /api/groups` with `view=albums|artists|genres|decades|years`, `q`, `root`, `filter`, `tag_field`, `sort`, `direction`, `offset`, and `limit`. Results contain stable group `key` values, labels, album credit/year summaries, group counts, duration, queued count, and the distinct underlying `total_tracks`. `POST /api/groups/paths` accepts `view`, `root`, and either `keys` or `all_matching: true` plus search/filter criteria; it returns group keys and deduplicated whole-group paths, rejecting selections exceeding 5,000 tracks. Track list/path endpoints accept `filter=tag_search` and `tag_field=all` or a supported metadata field name. Existing genre endpoints remain available for compatibility and editor suggestions.

## Current validation boundary

This build has been tested on Linux with generated files for every listed format and local HTTP API checks. DSM installation and operation have also been exercised by a DS1817+ user, but this specific update has not yet been retested on that NAS. Treat the SPK as a test build until it passes device validation. The package does not bundle `fpcalc`, so fingerprint lookup is unavailable until a compatible binary is installed.
